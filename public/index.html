THE IDEA

A review trail, not a victory badge.

Roadtest starts with a short list of claims, then records the checks that actually support each one. A pass applies only to that scope.

⌁
01 / FIRST VISIT

Walk in fresh

A clean browser follows the visible path a new user would take. No preconnected wallet or hidden test state.

{ }
02 / PUBLIC READS

Ask the product

Check public endpoints, contract identity, and current state against specific expected values.

◎
03 / RECEIPTS

Follow the transaction

A finalized hash only counts when consensus and execution both indicate success.

↗
04 / OPEN REPORT

Show the boundary

Publish the checks, source links, screenshot, and an honest list of paths that remain untested.

IMPORTANT CONTEXT

What this does not prove

    API responses are operated by the project. Browser screenshots come from the CI runner. They are useful review evidence, not cryptographic proof of every click or a security guarantee.

    BUILT FOR AGENTS TOO

    Let your agent read the receipts.

    No API key is needed for public reports. An agent can fetch the JSON, inspect each claim and transaction link, and decide whether the scope is enough for its own workflow. Teams can run the same test suite in CI against a configured target.
